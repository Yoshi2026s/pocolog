## 追加改善（基点4033b00）

- 同じライバー・日付のままアカウントを選んで移動。日数・時間では入力欄に配置し、長いスクロールや画面の開き直しを減らした。
- 実績入力欄から選択中のカレンダーの日付へ戻るボタンを追加。選択日へのフォーカスと、固定ヘッダーの下への移動を確認。日付ボタンの通常のTab操作も保持。
- 大きい表示でライバー名を折り返し、長い名前を読めるようにした。
- 負のエール、範囲外の時間、24時間超の入力がある場合、アカウント／ライバー移動や元の一覧への復帰を止め、未確定入力を画面に残したまま対象の入力欄へ戻す。

追加機能の検証: 320×568、390×844、844×390、1366×900で、同名の2アカウントを使い、切替だけで全月データが変わらないこと、0と未記録・メモ・日別実績が混ざらないこと、選択日の維持、エラー時の移動抑止、修正後の移動、カレンダー往復、長い名前の折り返し、通常の名前画面でアカウント切替を隠すことを確認。6サイズの入力・取消・達成表示・共有読込検証も再実行した。実績入力前へ戻す基準は組み合わせを開き直した時点になることを検査した。

## 続けて行った改善（基点fbaed13）

上の追加改善はPages run 41817448163で公開成功を確認してから、次の点検・改善を開始した。

- 日付移動で、24時間超などの未保存の入力が消える問題を再現し修正。カレンダー・前後日・今日・履歴・未記録候補の各経路が共通の検証を使い、エラー時の入力と日付を保持する。
- 時間加算・コピー・まとめ反映も不正な入力を上書きしない。保存済み記録は変更せず、明示的な消去・取消は利用可能。
- 日別エラーを時間入力欄の直下へ移動し、aria-invalid・aria-describedbyと枠色で対象を表示。再読込や修正時に古いエラー状態を解除。
- 「入力を終える」で数値欄からフォーカスを外し、キーボードを閉じる。Enter／次へ／完了のヒントも対応。変換中・keyCode229では移動しない。値を再加算したり共有保存したりしない。

320×568、390×844、430×932、667×375、844×390、1366×900で、負数・60分・24時間30分、修正後の復帰、入力完了での値保持、時間→分→完了、変換確定保護、月初／月末の移動制限、以前のライバー単位の入力、アカウントの予定カレンダーを確認。エラー状態での各移動・加算・コピーが全月の記録を変更しないことを比較した。既存の6サイズの共有読込・取消・達成表示検証、アカウント切替検証、回転・表示メニュー検証も再実行した。外部通信は模擬実装に限定し、本番の共有データは保全した。

## 手入力の取消改善（基点214b043）

- 時間・分・日数チェックと、以前のライバー単位の実獲得エールについて、直前の有効な手入力を既存の取消操作で復元できるようにした。時間加算などの取消も維持。
- 取消ボタンを時間入力欄の直下へ移動。PCを含め44px以上、スマホは既存スタイルにより48px以上。
- 不正な未保存入力があると「未保存の入力を戻す」を表示。保存済みの値を欄に戻すだけで、記録・未共有フラグを変更しない。その後も保存済みの直前操作の取消を維持。
- 「まとめ入力を元に戻す」は、不正な下書きがあってもまとめ操作全体を取り消す。
