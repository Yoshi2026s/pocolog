# スマホ操作改善の検証（2026-11-04）

基点: main `db1c0c0`。AGENTS.md・README.mdを確認し、公開済みの検索・変換確定保護・カレンダー移動の実装を保持した。

## 変更と実測

- 横向きのヘッダーと下部メニューを圧縮。844×390の通常一覧で表の領域が146pxから243pxへ増加。
- エール選択の範囲移動・閉じる操作を固定し、数字のリストだけをスクロール。スマホの範囲ボタン・閉じるボタンは44px以上。
- 目標入力の取り消し通知を小画面で2段にし、取消ボタンを44px以上にした。
- スマホの月選択は16px。表示領域の高さが420px未満の場合、実績画面のライバー移動欄の固定を解除して入力領域を確保。入力欄への移動も実際の固定状態を参照。

## 検証方法と結果

Chromiumを使い、320×568、390×844、430×932、667×375、844×390、1366×900で同じ操作を実行し、修正後の再実行でも全サイズが成功。

- 目標選択、37〜48への移動、選択後の取消、初期空白フォーカス。
- 検索の絞り込み、日本語変換確定中のEnter抑止、通常Enterによる1件候補への移動。
- 月実績入力、達成セル・名前の済バッジ、入力前の値への取消による達成解除。
- 日数・時間のカレンダーから入力欄への移動（キーボードを出さない）、時間加算と取消、翌日への移動と前日時間のコピー。
- 表示領域を高さ300pxにしたキーボード模擬状態、縮小と復元、入力画面の横はみ出しなし。
- 実際のshared.jsとSharedStateを使用し、Firebaseの通信部分だけをローカルの模擬実装に置換。起動時読込、未共有入力がある状態での更新保護、明示的読込のバックアップダウンロード、読込後の達成表示を検証。前月・メモ・日別記録を含む全データの一致も検査。
- 既存の32テストと本番用ビルド、差分検査が成功。

検証では外部通信を遮断し、共有データへの書込みは行わない。Firebase設定・ルール・既存データは変更していない。物理端末、iOSの実キーボードとSafariの実機検証は未実施。

追加の回転・表示検査では、320×568、360×640、375×667、600×320、667×375、844×390、768×1024、1024×768、1366×900を同じ画面で順に切り替え、最後に320×568へ戻した。各サイズで集中表示／大きい表示、エールのEnd・矢印・Enter操作、範囲移動後のキャンセルと値保持、色分け／その他メニューの画面内配置、半角カナのアカウント検索を確認した。
