# 画面・スマホ表示確認（2026-11-03）

基点は GitHub main `c33cc3259446bfd13756da7beb7092a3cc4e145c`。実ブラウザーの画面サイズを変更して確認したもので、物理スマートフォンでの検証ではない。

## 修正

- スマホ用スタイルで月表示切替が高さ30px、実績の移動・時間加算などが40pxになっていた。月切替・検索・追加・共有ボタン、メニュー、実績入力、エール選択肢を48px以上の高さにした。
- 1アカウント表示の締め・解禁日を幅48pxにし、入力欄・名前も高さ48pxにした。「文字・入力欄を大きく」でも行高とアカウント幅を確保した。
- 全アカウントのコンパクト一覧は既存の密度を保つ。狭い欄を編集するときは「表示」から1アカウント表示または大きい表示を利用できる。
- PRで既存のテストと本番と同じビルドを行う `Check Pocolog` を追加。
- 公開後の実測で、実績ダイアログ内の既存セレクターが一部の48px指定より優先されていたことを確認。ダイアログとカレンダーを指定したルールで修正し、再検査・再公開する。

## 確認結果

- 目標エールの選択変更と「元に戻す」。
- 名前検索の絞り込みと該当行への移動、1アカウント表示への切替。
- 月目標・月実績・日数／時間の切替。
- 組み合わせ別の現時点の獲得エール、時間加算、時間加算の取消、次のライバーへの移動。
- 4K・30分の検証入力が新しいタブでも復元されること。
- 幅390px、幅320pxの実績入力と667×375pxの低い画面でダイアログに横はみ出しがないこと。320pxでは主要ボタンを計測し、高さ48pxを確認。
- 既存26テスト、ビルド、差分検査。

検証入力は独立したブラウザーのローカル環境のみ。「共有先に保存」は実行せず、本番の記録やFirebase設定・ルールは変更していない。ローカル検証記録を共有元へ戻す操作でブラウザー制御が応答待ちになったため、検証用環境の復元完了は確認できていない。

物理端末のタッチ、OSキーボード、セーフエリア、JSON入出力の画面操作、本番への共有書込みは今回未検証。ブラウザー制御の応答待ちにより、一部のクリックはキーボード操作で切り分けた。
